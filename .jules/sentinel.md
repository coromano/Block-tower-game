## 2026-08-01 - [Missing Address Constraint for Protocol Account]
**Vulnerability:** The Anchor smart contract lacked an address constraint on the `tesoreria` (treasury) account inside the `ComprarBloque` context (`programs/casino_solana/src/lib.rs`). An attacker could have bypassed it by providing their own arbitrary account for `tesoreria` and pocketing the SOL transfer during block purchases.
**Learning:** In Solana/Anchor, unvalidated accounts representing static protocol destinations (like treasuries or commission wallets) must strictly enforce the expected `Pubkey` address to ensure that funds are directed to the correct, authorized destination instead of attacker-controlled accounts. The frontend `TESORERIA_WALLET` address was also using an invalid placeholder `11111111111111111111111111111111`, demonstrating lack of sync.
**Prevention:** Always use the `#[account(mut, address = pubkey!("..."))]` constraint for critical constant destinations when designing Anchor contexts. Synchronize these hardcoded public keys carefully with the client.
