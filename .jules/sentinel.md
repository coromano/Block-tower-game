## 2025-02-14 - Prevent Arbitrary Accounts in Smart Contract
**Vulnerability:** The `tesoreria` account in `ComprarBloque` was passed in without `address` constraint, allowing malicious users to potentially siphon or redirect funds intended for the treasury by providing their own account.
**Learning:** In Solana smart contracts, accounts representing constant destinations for protocol funds (like treasuries or commission wallets) must explicitly validate their address using an `address` constraint to prevent attackers from supplying arbitrary accounts and siphoning funds. Using the `pubkey!` macro inside an Anchor smart contract requires the `solana-program` crate to be explicitly added to the project's dependencies in `Cargo.toml`. When doing so with `anchor-lang = "0.32.1"`, lock `solana-program` to version `2.3.0` (or compatible) to avoid `__Pubkey` vs `Pubkey` type mismatch errors.
**Prevention:** Always validate statically known account addresses using the `address = ...` constraint and a predefined `Pubkey` constant. Include tests to verify expected failures when sending funds to unexpected accounts.
