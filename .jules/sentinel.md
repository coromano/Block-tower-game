## 2024-05-25 - [Missing Address Constraint on Treasury Account]
**Vulnerability:** The `tesoreria` account in `ComprarBloque` uses `/// CHECK:` without explicitly validating the address constraint `#[account(mut, address = pubkey!("..."))]`. This allows a malicious user to pass any account as `tesoreria` and intercept the funds transferred during block purchases.
**Learning:** In Solana smart contracts, accounts representing constant destinations for protocol funds (like treasuries or commission wallets) must explicitly validate their address using an `address` constraint to prevent attackers from supplying arbitrary accounts and siphoning funds. Also, always ensure the public key used matches the correct expected treasury wallet and that it exists in the codebase or environment. Avoid using the Solana System Program ID or random dummy keys in constraints unless explicitly verified. Avoid unwarranted arithmetic refactors when making targeted security fixes.
**Prevention:** Always use `#[account(address = pubkey!("..."))]` for known treasury or commission accounts. Use the `pubkey!` macro for compile-time checking. Ensure that the active `TESORERIA_WALLET` public key is used.
